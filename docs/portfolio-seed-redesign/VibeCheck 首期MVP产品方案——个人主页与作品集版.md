# VibeCheck 首期MVP产品方案——个人主页与作品集版

> 产品形态：Vibe Coding 作品社区  
> 数据内核：结构化作品档案、生命周期事实与复用关系  
> 首期品类：公开可访问、由 AI 编程工具辅助开发的个人主页与作品集 Web 网站  
> 文档版本：品类切换版 v1.0  
> 日期：2026 年 8 月

## 一、方案总则

### 1. 产品形态

VibeCheck 首期采用“社区前台＋结构化作品档案内核”的产品形态。用户可以像使用创作社区一样浏览截图、收藏参考、点赞、评论、关注更新、分享和发布作品；每一个社区内容单元同时对应一份具有唯一作品 ID、来源、验证时间和历史记录的作品档案。

社区负责形成低门槛的视觉消费和重复访问，结构化档案负责把“喜欢”转化为可筛选、可比较、可复用的开发信息。产品必须同时满足“值得逛”和“能推进创作”两个要求。

个人主页与作品集只是首期 Category。通用作品身份、作者、状态、生命周期、资产、关系和证据使用 `ProjectCore`；网站类型、作者身份、用途、结构、模块、视觉和交互等首期专属字段使用 `PortfolioSchemaV1`。

### 2. MVP 目标

首期 MVP 建立以下完整闭环：

**浏览作品获得灵感—收藏参考—搜索或查同类—结构化比较—访问/Fork 复用资产—开始或调整开发—发布自己的作品—声明参考与复用关系—持续更新—再次被发现。**

MVP 需要验证：

1. 强视觉作品能否带来稳定浏览、收藏与回访；
2. 结构化信息能否帮助用户确定网站类型、首页结构、项目展示和视觉方向；
3. 源码、Starter、模板和组件是否会产生真实开发行为；
4. 完成个人网站的用户是否愿意发布回流；
5. 新作品是否愿意引用旧作品、模板或组件，形成可验证关系。

### 3. 成功定义

首期成功不能由访问量、注册量、点赞量或作品数量单独判断。社区侧需要出现深度浏览、收藏和回访；决策侧需要出现比较、资产访问与开发行动；供给侧需要出现发布、更新与关系声明；数据侧需要达到作品密度、字段完整度、证据覆盖和状态时效门槛。

北极星指标统一为：**每周完成有效作品发现并产生创作推进动作的创作者数。**

## 二、首期边界

### 1. 收录范围

作品必须具有公开独立 Web 地址、明确个人身份和实质内容结构，主要内容无需登录即可访问，并存在 AI 编程工具辅助开发的作者声明或公开证据。首页至少包含个人介绍，以及项目、经历、服务、研究、作品或内容中的一项。

首期覆盖通用个人主页、开发者作品集、设计师作品集、产品经理作品集、创作者/自由职业者主页、学生/应届生作品集、在线简历型网站和学术个人主页。

### 2. 混合形态

- 个人主页＋博客：个人身份、项目或经历为主体时收录，博客作为能力字段；纯文章消费站排除。
- 个人主页＋作品集：项目展示为主时归为 Portfolio；两者权重接近时标记混合型。
- 个人主页＋在线简历：具有独立 Web 结构时收录；只有文件预览或下载时排除。
- 个人主页＋服务：个人/自由职业者身份为主体时收录；企业或团队品牌为主体时排除。
- 学术主页＋出版物：研究者身份和研究资料为主体时收录；简单链接列表排除。

### 3. 排除范围

| 排除方向 | 具体内容 | 原因 |
| --- | --- | --- |
| 非个人主体 | 企业官网、公司产品官网、团队品牌官网 | 不符合个人身份与作品表达边界 |
| 内容不足 | 纯 Link-in-bio、单张电子名片、简单链接页 | 缺少可比较的页面结构和内容模块 |
| 平台资料页 | 招聘平台主页、社交主页、Notion 公开页 | 缺少独立作品形态或受平台结构主导 |
| 文件而非站点 | 纯简历 PDF、图片或演示文件 | 不具备 Web 站点体验和生命周期 |
| 访问或证据不足 | 无法公开访问、主要内容需登录、无法确认 AI 辅助开发 | 无法形成可信档案和公开比较 |
| 泛社区内容 | 无作品挂靠的观点帖、日常动态和推广帖 | 稀释作品社区与数据内核 |
| 重社交/交易 | 私信、粉丝等级、复杂积分、平台内支付 | 不能直接验证首期核心闭环 |

## 三、用户状态与核心任务

| 用户状态 | 核心任务 | MVP 入口 | 目标行为 |
| --- | --- | --- | --- |
| 灵感浏览者 | 发现好看的个人网站并保存参考 | 作品广场、分类、视觉专题、动态 | 收藏、关注、查同类 |
| 准备开发者 | 确定网站类型、结构、风格和起点 | 搜索、查同类、详情、比较 | 保存参考、开始开发 |
| 开发中创作者 | 解决具体模块、动画和实现问题 | 筛选、比较、资产、关系 | 调整方向、复用资产 |
| 已发布作者 | 展示并维护个人网站 | 发布、更新、作者主页 | 发布、更新、开放资产 |
| 复用贡献者 | 说明源码/模板/组件的使用边界 | 资产区、关系声明 | 形成已证实复用关系 |
| 平台编辑 | 建立密度并维护可信度 | 后台 | 建档、分类、审核、复核 |

灵感浏览者进入首期核心用户范围。首页和卡片必须首先服务视觉判断，但需要通过收藏、查同类、比较和资产入口把浏览转化为创作推进动作。

## 四、核心用户场景

### 1. 无明确计划时浏览灵感

用户从编辑精选、最新发布、最近更新、开源可 Fork、网站类型、视觉方向或优秀 Case Study 进入作品流。卡片以真实截图为主，辅助展示网站类型、作者身份、视觉/布局标签、核心模块、资产状态和访问状态。

用户可直接收藏、关注更新或加入比较。连续查看相似作品时，系统提示“查看同类”或“比较结构”，不要求用户先填写完整需求。

### 2. 已有方向时查同类

用户可以输入“极简风产品经理 Portfolio”“Next.js 开发者作品集”“单页暗色个人网站，有项目展示和博客”“可以直接 Fork 的个人主页”等自然语言查询。

系统解析作者身份、网站类型、建站目的、页面结构、内容模块、项目展示、视觉风格、布局、主题、交互、技术实现和复用条件，并允许用户逐项确认或修改。

### 3. 比较结构与设计方向

用户从卡片、详情或结果页选择 2—5 个作品，比较定位与用途、内容结构、项目展示、视觉方向、交互动画、站点能力、实现方式、复用条件以及状态与证据。

比较完成后，用户可保存参考、开始开发、调整方向、复用资产或暂不开发；“暂不开发”作为次级选项，不作为页面主要价值文案。

### 4. 复用资产开始开发

用户在详情或比较页查看完整源码、Starter、模板、页面布局、组件、动画、主题、博客/CMS 模块、部署配置、提示词和设计稿。资产卡固定区分可用状态、许可、价格和获取方式。

用户点击 Fork、Clone 或 Use template 时记录复用意向；完成自己的作品后，可将该行为转化为基于模板、使用组件、Fork 或源码派生关系。

### 5. 发布作品并声明来源

作者输入公开 URL，系统先完成格式、安全、访问、重复和品类检查。未发现档案时创建草稿并自动预填；发现已有档案时默认进入已有详情，只有作者需要管理权限时才进入低频身份验证。

新作品发布时，作者可以选择关联收藏或比较记录，并声明参考作品、模板、组件或代码来源。关系声明作为 P0.5 能力，不阻断 P0 基础发布。

### 6. 持续更新与回访

作者可以记录新增项目、Case Study、博客、简历更新、视觉改版、主题变化、技术栈变化、开放源码和站点重新定位。更新同步写入作品档案、生命周期时间线、公共动态和关注通知。

## 六、作品广场首页

### 1. 页面目标

首页让用户无需理解分类体系即可开始浏览，并在首屏同时知道“这里有什么、可以怎样找、如何发布”。首期不以统计数字或综合热度制造繁荣感。

### 2. 首页频道

| 顺序 | 频道 | 内容规则 | 主要动作 |
| --- | --- | --- | --- |
| 1 | 首屏与统一搜索 | 主表达、自然语言搜索、快捷查询、探索/发布双行动 | 搜索、探索、发布 |
| 2 | 编辑精选 | 视觉、结构、完整度和实际可访问性具有代表性的作品 | 详情、收藏、比较 |
| 3 | 最新发布/最近更新 | Tab 展示首次发布和有效生命周期事件 | 浏览、关注、定位事件 |
| 4 | 开源可 Fork | 具有源码、Starter、模板或可 Fork 入口 | 查看资产、Fork、比较 |
| 5 | 按个人网站类型探索 | 通用主页、开发者、设计师、产品经理等策展子群 | 进入专题 |
| 6 | 按视觉方向探索 | 极简、编辑感、暗色科技、高交互、实验性等动态专题 | 收藏、查同类 |
| 7 | 优秀项目 Case Study | 项目叙事深度和结构具有参考价值的作品 | 比较展示方式 |
| 8 | 可直接复用的起点 | Starter、模板、布局、组件和设计系统 | 获取资产、开始开发 |
| 9 | 已结束但仍可复用 | 已暂停/结束但资产仍有效的作品 | 查看历史、复用资产 |

视觉方向专题属于运营可配置标签，不写死为一级品类。频道中的所有作品卡片引用同一个 `project_id`，不得复制独立内容对象。

### 3. 作品卡片

截图是卡片第一信息层，必须使用真实站点截图或明确的待补媒体状态。卡片固定展示：

- 作品名称、一句话定义和作者；
- 网站类型与作者身份；
- 2—3 个最有区分度的视觉、布局或结构标签；
- 核心模块或项目展示摘要；
- 开源、模板、可 Fork 或组件资产标签；
- 访问状态与最后验证时间的简短表达；
- 收藏参考、加入比较和资产入口；点赞、评论作为弱互动。

卡片不展示完整字段、证据公式或综合分数。加入比较、收藏参考和资产入口的视觉优先级高于点赞。

## 七、分类、搜索与查同类

### 1. 分类体系

分类页以策展入口组织内容，筛选和比较使用结构化字段。P0 分类维度为：

| 维度 | 用途 | 示例 |
| --- | --- | --- |
| 网站类型 | 判断作品的整体形态 | 个人主页、Portfolio、在线简历、学术主页、混合型 |
| 作者身份 | 找到与自己表达任务相近的创作者 | 开发者、设计师、产品经理、创作者、自由职业者、学生、研究者 |
| 建站目的 | 判断首页和内容组织的核心目标 | 展示项目、求职、个人品牌、获客、学术展示、内容沉淀 |
| 页面结构 | 选择单页、多页或混合结构 | 单页、多页、混合 |
| 核心模块 | 决定信息架构 | About、Projects、Experience、Services、Blog、Contact 等 |
| 项目展示 | 比较项目呈现方式 | 卡片、画廊、时间线、案例长页、仓库列表、混合 |
| 视觉与布局 | 选择设计方向 | 极简、编辑感、科技、粗野、插画；网格、分屏、全屏等 |
| 主题与色彩 | 比较明暗和色彩表达 | 浅色、暗色、可切换；单色、中性、品牌色、鲜艳 |
| 交互 | 评估动画成本 | 静态、轻交互、中等、高交互；滚动、转场、3D 等 |
| 站点能力 | 判断博客、响应式和 Case Study | 响应式、博客、深度 Case Study |
| 实现与复用 | 选择技术和起点 | AI 工具、技术栈、部署、源码、Starter、模板、组件 |

CMS、多语言、联系方式、简历下载和 AI 功能进入 P1 采集与筛选。

### 2. 自然语言意图

意图解析字段及初始权重：

| 匹配组 | 字段 | 权重 |
| --- | --- | --- |
| 定位 | 作者身份、网站类型、建站目的 | 25% |
| 视觉方向 | 视觉风格、布局、主题、色彩 | 25% |
| 结构与项目展示 | 页面结构、核心模块、展示方式、Case Study 深度 | 25% |
| 实现方式 | AI Coding 工具、技术栈、部署 | 10% |
| 复用条件 | 开源、可 Fork、模板和资产类型 | 10% |
| 状态与时效 | 访问状态、验证时间、完整度 | 5% |

“目标用户”不再作为高权重搜索字段；首期使用“作者身份、网站类型和建站目的”表达谁在建设、为何建设。

### 3. 结果与同类分析

普通搜索结果显示可解释匹配原因，例如“同为产品经理＋极简风”“同为单页暗色＋项目展示＋博客”“使用 Next.js 且可 Fork”。

同类分析展示代表作品、常见结构组合、视觉方向、项目展示方式、复用资产分布和状态分布。作品数量不得被解释为竞争强度、需求强弱或职业机会。

精确结果少于 3 个时，分区展示精确结果与放宽后的相邻结果；不得伪造作品密度。

## 八、作品详情

作品详情是社区内容页与结构化档案的统一载体。

| 区域 | 核心内容 | 主要动作 |
| --- | --- | --- |
| 视觉展示 | 多张桌面/移动截图、名称、定义、作者、类型、状态 | 访问网站、收藏、关注、分享、比较 |
| 参考亮点 | 编辑或作者说明“最值得参考什么” | 保存参考、查看同类 |
| 定位与结构 | 作者身份、用途、页面结构、内容模块和信息架构摘要 | 查看来源、进入筛选 |
| 项目展示 | 展示形式、Case Study 深度和项目叙事 | 比较展示方式 |
| 视觉与交互 | 风格、布局、色彩、主题、交互等级和动画方式 | 查相似、加入比较 |
| 站点能力 | 响应式、博客及 P1 能力 | 筛选相同能力 |
| 开发信息 | AI 工具、技术栈、部署、仓库 | 查看实现、访问仓库 |
| 复用资产 | 类型、许可、价格、获取方式和可用状态 | Fork、Clone、获取、声明使用 |
| 生命周期 | 当前状态和事件时间线 | 关注、报告、作者确认 |
| 作品关系 | Inspired by、参考、Fork、Remix、模板、组件和源码派生 | 查看来源/衍生、声明关系 |
| 讨论 | 使用反馈、开发问题、复用反馈和状态补充 | 评论、回复、举报 |

关键字段展示来源类型与最后验证时间；未知、过期、争议和系统推断不得被隐藏或自动补全。

## 九、作品比较

### 1. 比较目标

比较页帮助用户回答：

- 我想做哪一种个人网站？
- 首页和导航应该采用什么结构？
- 项目经历应该用卡片、画廊还是深度 Case Study？
- 是否需要博客、暗色模式或高强度动画？
- 哪些视觉方向与作者身份、建站目的匹配？
- 哪些源码、Starter、模板或组件可以直接作为起点？

### 2. 比较维度

| 维度 | P0 比较行 |
| --- | --- |
| 定位与用途 | 网站类型、作者身份、建站目的、一句话定义 |
| 内容结构 | 单页/多页、导航方式、核心模块、首页内容顺序 |
| 项目展示 | 展示形式、Case Study 深度、项目详情入口 |
| 视觉方向 | 视觉风格、布局方式、色彩特征、主题模式 |
| 交互动画 | 交互等级、滚动动画、页面转场、微交互、3D/WebGL 等 |
| 站点能力 | 响应式、博客、深度 Case Study；P1 补充 CMS、多语言等 |
| 实现方式 | AI Coding 工具、技术栈、部署和仓库 |
| 复用条件 | 源码、Starter、模板、组件、设计稿、许可和获取方式 |
| 状态与证据 | 访问状态、最后验证时间、信息完整度和来源 |

相同项可折叠，差异项突出，缺失项明确显示未知原因。异常或结束作品保留历史与资产，不从比较中自动移除。

### 3. 行动记录

行动枚举统一为：保存参考、开始开发、调整方向、复用资产、暂不开发。用户可选择受影响的 Category 字段或通用实现/资产字段，保存原因和关联资产。

`DecisionRecord` 使用字段引用路径保存受影响内容，例如 `category_data.visual_styles` 或 `project_core.tech_stack`，不得把 Portfolio 字段硬编码进通用决策对象。

## 十、复用资产与作品关系

### 1. 资产模型

| 资产类型 | 典型内容 |
| --- | --- |
| 完整源码 | 可运行站点仓库或完整代码包 |
| Starter | 含基础配置、路由和部署结构的起始项目 |
| 模板 | 可复制的完整页面或站点模板 |
| 页面布局 | Hero、项目区、案例页等结构方案 |
| UI 组件 | Hero、导航、项目展示、联系等组件 |
| 动画/交互 | 页面转场、滚动动画、光标、3D/WebGL 模块 |
| 主题/设计系统 | Token、字体、颜色、组件规范和主题包 |
| 简历模块 | 经历、教育、技能和下载组件 |
| 博客/CMS 模块 | 内容模型、博客页面、CMS 配置 |
| 部署配置 | 构建、域名、CI/CD 和平台部署配置 |
| 提示词 | 用于生成结构、文案、代码或视觉方向的提示词 |
| 设计稿 | Figma 等可获取的页面设计文件 |

每项资产保存名称、说明、类型、子角色、URL、许可、价格、获取方式、可用状态、来源作品、证据和最后验证时间。可用状态、许可和价格使用固定顺序展示，避免互相混淆。

### 2. 关系优先级

- P0：展示平台已建立的作品关系和关联资产。
- P0.5：作者或用户声明 `inspired_by`、`reference`、`fork`、`remix`、`based_on_template`、`uses_component`、`source_derivative`，进入审核与确认流程。
- P1：同一 Starter 聚类、同设计结构变体、派生数量和关系网络视图。

关系统一保存源作品、目标作品、方向、关联资产、声明者、证据、确认状态和最后验证时间。单方声明不得显示为双方确认或平台核验。

## 十一、发布、作者验证与更新

### 1. 发布流程

1. 输入 URL，检查格式、安全、访问、重复和品类；
2. 自动预填名称、定义、截图、仓库、开发工具和基础状态；
3. 确认网站类型、作者身份、用途、页面结构和核心模块；
4. 补充项目展示、视觉、布局、主题、交互、技术和资产；
5. 预览卡片与详情摘要后提交审核。

P0 作者发布不要求一次填满全部 P1 字段；P0 核心比较字段必须达到提交要求。自动提取结果保留来源并允许纠正。

### 2. P0.5 关系声明

发布编辑增加可跳过的“参考与复用来源”模块。用户可从历史收藏、比较会话或 URL 搜索选择来源作品，并指定关系与资产。跳过不影响 P0 发布；填写后与作品一并进入审核。

### 3. 已有档案作者身份验证

查重命中已有档案时禁止默认新建。作者需要管理权限时，可通过域名、代码仓库、原发布账号、公开个人主页或人工材料证明身份。验证材料只用于审核，不公开展示。P0 采用人工审核，自动验证进入 P1。

### 4. 更新类型

作者可发布版本、地址、状态、资产和说明更新；Portfolio 变更子类型包括新增项目、Case Study、博客、简历更新、视觉改版、主题变化、技术栈变化、开放源码和站点重新定位。每次更新保存前后值、来源和影响范围。

## 十二、社区机制

社区基础单元是作品，动态单元是围绕作品发生的生命周期事件。作品首次发布、版本更新、新增项目、视觉改版、开放资产、域名迁移、状态变化和新增关系均可进入动态流。

| 互动 | 用户价值 | 数据价值 | 优先级 |
| --- | --- | --- | --- |
| 收藏参考 | 保存灵感与候选方案 | 形成长期兴趣和回访入口 | P0 |
| 关注更新 | 接收改版、项目、资产和状态变化 | 分发生命周期内容 | P0 |
| 加入比较 | 从浏览进入结构化选择 | 连接社区与开发行动 | P0 |
| 访问/Fork 资产 | 获得直接开发起点 | 形成复用意向 | P0 |
| 点赞 | 低成本表达认可 | 弱质量信号 | P0 |
| 评论与回复 | 交流体验、实现和复用问题 | 补充问题线索 | P0 |
| 声明关系 | 说明参考或使用了哪些来源 | 建立真实作品网络 | P0.5 |
| 状态报告 | 提交失效、迁移和错误 | 提高数据时效 | P1 |

自然排序优先使用匹配度、可比较性、证据、时效和资产价值；互动量不能覆盖这些信号。

## 十三、数据模型

### 1. 通用对象

`ProjectCore` 保存作品身份、作者关系、URL、历史地址、媒体、仓库、AI Coding 工具、技术栈、部署、当前状态、生命周期、资产、关系、证据和审核状态，并通过 `category_id`、`category_schema_version`、`category_data` 挂载品类数据。

### 2. PortfolioSchemaV1

| 优先级 | 字段组 | 字段 |
| --- | --- | --- |
| P0 | 定位 | 网站类型、作者身份、建站目的 |
| P0 | 结构 | 页面结构、核心内容模块、导航/首页组织摘要 |
| P0 | 项目展示 | 展示形式、Case Study 深度 |
| P0 | 视觉 | 视觉风格、布局方式、色彩特征、主题模式 |
| P0 | 交互 | 交互等级、动画/交互方式 |
| P0 | 能力 | 响应式、博客能力 |
| P1 | 增强能力 | CMS、多语言、联系方式、简历下载、AI 功能 |

Category 字段不复制技术栈、资产、状态、证据和作者主对象字段。

## 十四、生命周期与状态

通用事件枚举为：首次发现、首次发布、版本更新、域名迁移、链接异常、恢复、暂停、结束、新增资产、新增关系。Portfolio 变更作为版本更新的结构化子类型保存。

访问状态继续使用正常可访问、需要登录、等待复检、部分异常、链接不可用、疑似迁移、暂停、结束、恢复和未知等通用枚举，以兼容历史和未来品类。新收录作品的主要内容必须无需登录；`login_required` 只能作为后续状态或历史兼容状态，不是合格的初始收录状态。

首次异常只进入待复查，不自动变更为链接失效；暂停、结束和原因需要作者声明、公开公告或充分证据。

## 十五、冷启动与持续供给

正式种子库为 64 个作品，覆盖 8 个策展子群，每群至少 6 个；至少 24 个开源或可 Fork，至少 32 个包含复用资产，单一技术栈或 AI Coding 工具不超过 40%。

建档优先顺序：

1. 视觉和结构具有代表性且公开可访问；
2. P0 字段能够可靠核验；
3. 能支撑同类型内部比较与跨风格比较；
4. 包含开源、模板、组件或设计资产；
5. 覆盖不同状态和生命周期事件，但不为了状态多样性收录低质量作品。

新收录与高访问作品每 7 天检查一次，普通作品每 14 天检查一次，长期异常作品每 30 天检查一次。检查仅产生可验证的技术事实。

## 十六、功能优先级

### P0：社区与核心闭环

作品广场、视觉作品卡片、分类专题、最新动态、统一搜索、意图确认、同类分析、详情、收藏、点赞、关注更新、基础评论、2—5 个作品比较、行动记录、资产访问、发布、低频作者身份验证、作者主页、个人中心、作品更新、后台与埋点。

### P0.5：关系回流

发布时关联收藏/比较、声明参考与复用关系、关系证据提交、后台审核、单方/双方/平台确认状态，以及详情页来源和衍生展示。

### P1：关系与能力增强

作者关注、状态报告、变化通知、同 Starter 聚类、设计结构变体、轻量个性化、CMS/多语言等扩展字段和筛选、作者身份自动验证。

### P2：规模化扩展

完整作品关系图谱、标准化许可、平台内交易、作者高级监测、线索管理、跨品类推荐和数据服务。排行榜、粉丝等级和私信不因社区形态自动提前。

## 十七、指标与埋点

### 1. 北极星指标

每周完成有效作品发现并产生创作推进动作的创作者数。有效动作包括收藏参考、开始/完成比较、资产/Fork 访问、保存开发行动、发布或更新；点赞、评论、分享单独不计入。

### 2. 核心指标

| 指标组 | 指标 |
| --- | --- |
| 浏览 | 作品流到详情率、详情深访率、收藏参考率、关注率、次周回访率 |
| 查同类 | 有效匹配率、意图确认率、匹配原因使用率 |
| 比较 | 比较发起率、比较完成率、开发行动保存率 |
| 复用 | 资产点击率、Fork/模板使用意向、关系声明率、关系确认率 |
| 回流 | 发布完成率、60 天新作品回流率、新作品引用旧作品比例 |
| 生命周期 | 作品更新率、有效事件点击率、关注通知回访率 |
| 数据 | P0 字段完整率、证据覆盖率、30 天状态有效率、重复作品率 |

### 3. 核心事件

至少记录 `home_viewed`、`project_card_clicked`、`project_detail_engaged`、`reference_saved`、`project_followed`、`search_submitted`、`intent_confirmed`、`comparison_added`、`comparison_started`、`comparison_completed`、`asset_opened`、`fork_intent_recorded`、`decision_saved`、`project_submitted`、`relation_declared`、`relation_confirmed`、`author_verification_submitted` 和 `project_updated`。

事件关联用户或匿名会话、`project_id`、`category_id`、来源页面、查询意图和时间；不得在埋点中保存身份验证私密材料或完整自由文本。

## 二十、风险与应对

### 1. 退化为普通 Portfolio 社区

若首页只突出截图、点赞和热门作品，平台会失去结构化差异。卡片和详情必须突出收藏参考、比较、资产和关系，排序继续受证据与可比较性约束。

### 2. 视觉标签主观且失控

视觉风格使用可运营字典和多标签，不尝试生成唯一“正确风格”。编辑标注、作者声明与系统推断分开保存，允许纠错和版本化。

### 3. 字段过多增加建档成本

P0 只保留影响参考选择和开发方案的字段；CMS、多语言、联系方式、简历下载和 AI 功能延后。卡片不堆叠完整档案字段。

### 4. 关系声明缺乏可信度

关系区分单方声明、双方确认和平台核验；必须保存方向、证据和关联资产，不以相似外观自动判断 Fork 或模板关系。

### 5. 品类字段污染通用模型

所有 Portfolio 字段进入版本化 `category_data`。跨品类字段只进入 `ProjectCore`，扩品类不得通过继续追加首期字段完成。

## 二十一、最终方案结论

VibeCheck 首期应以强视觉作品社区承接灵感浏览，以结构化档案承接选择与比较，以资产和关系承接复用，以发布和生命周期承接作品回流。个人主页与作品集提供充足、公开、视觉差异明显且资产丰富的作品供给，适合验证完整循环。

产品核心不是 Portfolio 模板目录，而是“作品广场—收藏参考—查同类—结构化比较—复用—发布—关系回流—持续更新”的 Vibe Coding 作品资产闭环。首期建立的 `ProjectCore`、Category Schema、证据、事件、资产和关系规则必须可以直接支持后续品类扩张。
