# VibeCheck 产品定位——个人主页与作品集首期品类版

> 面向 Vibe Coding 创作者的作品发现、发布与生命周期资产平台  
> 文档版本：品类切换版 v1.0  
> 日期：2026 年 8 月  
> 文档状态：首期战略基线

## 一、产品战略

VibeCheck 面向使用 AI 编程工具创作数字产品的个人创作者和小型创作团队，连接创作者从获得灵感、发现同类、选择结构与设计方向、比较实现方案、复用已有资产、完成开发、发布作品，到持续维护和开始下一次创作的完整过程。

平台的长期本质不因首期品类切换而改变：VibeCheck 仍然是面向 Vibe Coding 创作者的作品发现、发布与生命周期资产平台，不是个人网站社区、简历网站社区，也不是 Portfolio 模板商店。“公开可访问、由 AI 编程工具辅助开发的个人主页与作品集 Web 网站”只是 MVP 阶段用于建立首个高密度作品社区、验证完整循环的种子品类。

VibeCheck 的核心逻辑是由作品资产驱动的创作者循环。已经上线的作品向准备开发的创作者提供视觉参考、内容结构、项目展示方式、技术路径和可复用资产；创作者完成开发后，把新作品发布回平台，并声明参考、Fork、模板或组件关系；作品后续的改版、项目新增、域名变化、开放源码与状态变化继续沉淀为生命周期事实。

平台的核心单位是一份持续存在的作品档案，而不是一次性帖子。社区是前台产品形态；结构化档案、跨来源作品身份、生命周期事实、证据体系和复用关系才是长期数据资产。

## 二、产品定义

VibeCheck 是一个面向 Vibe Coding 作品的发现、发布与生命周期平台。创作者可以在开始开发前浏览真实作品，快速回答“我想做哪一种作品、采用什么结构和设计方向、哪些实现可以复用”；完成开发后发布自己的作品，使其继续被发现、比较、引用和更新。

首期，VibeCheck 聚焦个人主页与作品集网站，让用户通过高质量截图、结构化筛选、作品详情和比较理解：

- 不同身份的创作者如何表达自己；
- 个人信息、经历、项目与内容如何组织；
- 项目采用何种展示形式与 Case Study 深度；
- 视觉风格、布局、主题和动画如何组合；
- 使用了哪些 AI Coding 工具、技术栈和部署方式；
- 是否存在可以直接获取、Fork 或改造的源码、Starter、模板、组件和设计资产。

VibeCheck 提供可追溯的作品事实和参考入口，不根据作品数量、互动量、访问状态或仓库活跃度推断市场需求、职业能力、收入或商业成功。

## 三、定位表达

### 1. 一句话产品定位

VibeCheck 是面向 Vibe Coding 创作者的作品发现与生命周期平台：做之前看真实作品、定结构、选方向、找复用，做出来后发布、更新并留下可追溯的作品关系。

### 2. 首页主表达

先看看别人如何表达自己，再开始搭建你的作品。

### 3. 首页辅助表达

浏览真实的个人主页与作品集，比较页面结构、项目展示、视觉交互和实现方式；收藏参考、复用源码或模板，完成后发布自己的作品。

### 4. 作者侧表达

发布你的个人网站，持续记录改版、项目新增和开放资产，让作品被发现、参考和复用。

## 四、目标用户与用户状态

VibeCheck 的核心用户是使用 Cursor、Lovable、Bolt、v0、Replit、Claude Code、Codex 等 AI 编程工具完成 Web 作品的个人创作者和小型创作团队。职业不是准入条件，但首期内容会自然覆盖开发者、设计师、产品经理、创作者、自由职业者、学生、求职者和学术研究者。

| 用户状态 | 触发条件 | 核心任务 | 目标转化 |
| --- | --- | --- | --- |
| 灵感浏览者 | 关注个人网站与 Vibe Coding，但尚无明确开发计划 | 浏览高质量作品、收藏参考、形成偏好的风格与结构 | 形成具体方向或持续收藏关系 |
| 准备开发者 | 准备搭建个人主页或作品集 | 选择网站类型、内容结构、视觉方向和起始资产 | 开始开发或建立方案清单 |
| 开发中创作者 | 已开始搭建，存在具体设计或实现问题 | 查找相似实现、比较模块、复用源码/模板/组件 | 调整方案并完成发布 |
| 已发布作者 | 已有公开个人网站 | 发布作品、补充档案、记录版本、分享资产 | 形成持续档案和更新内容 |
| 复用贡献者 | 开放了源码、Starter、模板或组件 | 说明许可和获取方式、确认派生关系 | 形成可验证复用网络 |

“灵感浏览者”在首期具有战略重要性。个人主页与作品集具有强视觉属性，用户即使没有确定项目也会主动浏览、收藏并形成审美与结构偏好。社区浏览因此不再只是高意图检索前的入口，而是需求形成和重复访问的重要来源；但浏览最终仍应自然连接收藏参考、比较、复用、开发与作品发布。

## 五、核心用户问题

### 1. 优秀案例分散，参考成本高

个人网站散落在社交媒体、设计展示站、代码仓库、模板市场、建站平台展示页和独立域名中。截图、源码、设计说明、作者身份和技术实现通常彼此分离，用户需要反复搜索、去重和整理。

### 2. 视觉灵感难以转化为可执行方案

用户能快速判断一个网站“好看”，却不容易进一步拆解它属于什么类型、首页如何组织、项目如何展示、动画是否必要、博客是否值得建设，以及哪些部分可以直接复用。

### 3. 模板、源码与实际作品缺少关系

模板市场展示模板，代码仓库展示代码，作品社区展示成品，但用户难以确认一个真实网站基于哪个 Starter、使用了什么组件、一个模板产生了多少变体，以及复用是否受到许可限制。

### 4. 作品上线后缺少连续记录

个人网站会持续新增项目、更新简历、改版主题、迁移技术栈或开放源码。多数平台只记录首次发布，难以保留作品演进和复用关系。

### 5. 消费参考与发布回流没有连接

创作者开发前会保存大量参考，但完成自己的作品后，很少把“参考了谁、复用了什么、最后做成什么”重新沉淀为可发现的结构化案例。

## 六、核心价值主张

### 1. 面向浏览者与准备开发者

VibeCheck 让用户通过截图、策展频道和可解释筛选快速发现合适的参考对象，并从“喜欢这个网站”进一步走向“我选择哪种网站类型、页面结构、项目展示、视觉方向和技术方案”。

### 2. 面向开发中创作者

平台将外观相似与结构相似区分开来，支持比较内容模块、项目展示、布局、主题、交互、技术栈和可复用资产，帮助用户保存参考、开始开发、调整方向或采用现有资产。

### 3. 面向已发布作者

作者获得持续存在的作品档案、同类曝光、版本历史、状态检查、资产展示和派生关系。即使网站暂停或结束，公开源码、组件、设计稿和经验仍可继续被发现。

### 4. 面向平台长期资产

平台逐步积累跨平台作品身份、分类 Schema、生命周期事实、多源证据与真实复用关系，形成“这个作品参考了谁、由哪个 Starter 产生、哪些结构被反复采用”的作品网络。

## 七、产品核心循环

| 环节 | 用户或平台行为 | 产生的价值 |
| --- | --- | --- |
| 作品进入 | 平台发现或作者提交个人网站 | 建立可浏览、可检索的作品供给 |
| 灵感发现 | 用户浏览截图、频道和专题 | 形成风格偏好与创作方向 |
| 收藏与查同类 | 用户保存参考并检索相似作品 | 将低意图浏览转为具体方案探索 |
| 结构化比较 | 对比结构、项目展示、视觉、交互、实现与复用条件 | 形成可执行的开发选择 |
| 复用与开发 | 用户访问资产、Fork、采用模板或组件 | 作品信息转化为实际开发行为 |
| 新作品上线 | 用户完成个人网站 | 产生新的作品供给 |
| 发布与关系回流 | 用户发布作品并声明参考/复用关系 | 建立可验证的作品网络 |
| 生命周期积累 | 作者和平台持续记录改版、资产和状态 | 提高下一轮发现与比较的可信度 |

核心循环压缩为：

**作品进入—作品被发现—收藏/比较/复用—完成开发—新作品发布回流—持续更新—服务下一轮创作者。**

## 八、首期种子品类

### 1. 一级类别

首期一级类别统一为：**公开可访问、由 AI 编程工具辅助开发的个人主页与作品集 Web 网站。**

以下形态作为同一一级类别下的策展子群，而不是独立产品类别：

| 策展子群 | 识别重点 |
| --- | --- |
| 通用个人主页 | 以个人身份、简介、经历与链接为主，具有完整独立站点形态 |
| 开发者作品集 | 强调项目、代码、技术栈和开发经历 |
| 设计师作品集 | 强调视觉作品、案例过程、图像与动效呈现 |
| 产品经理作品集 | 强调产品案例、问题拆解、方法与结果表达 |
| 创作者/自由职业者主页 | 强调个人品牌、服务、内容与合作入口 |
| 学生/应届生作品集 | 强调学习经历、项目能力和求职表达 |
| 在线简历型网站 | 以经历、技能、教育和可下载简历为主，但具有独立 Web 结构 |
| 学术个人主页 | 强调研究方向、论文、项目、教学与公开资料 |

策展子群由网站类型、作者身份与建站目的共同派生，不写入 `ProjectCore` 固定枚举。

### 2. 收录条件

作品必须同时满足：

1. 存在稳定、可公开访问的独立 Web 地址，主要内容无需登录即可查看；
2. 围绕一个明确个人或明确署名的独立创作者身份组织内容；
3. 至少包含主页介绍，以及项目、经历、服务、研究、作品或内容中的一项实质模块；
4. 具有独立作品形态，不只是平台账号、单张名片或文档附件；
5. AI 编程工具辅助开发具有作者声明、构建平台信息、公开仓库、发布记录或可信外部来源之一；
6. 页面内容、截图和访问状态能够被平台在合法范围内核验并记录证据。

无法确认 AI 辅助开发的候选可进入内部待核验队列，但不得作为首期公开作品进入核心推荐与比较。

### 3. 混合形态归类规则

- **个人主页＋博客**：主页仍以个人身份、作品或经历为主，博客作为能力标签；若首页和主要导航几乎全部服务文章阅读，则按纯博客排除。
- **个人主页＋作品集**：以项目展示和案例阅读为主时归入 Portfolio；身份介绍与项目展示权重接近时标记为混合型。
- **个人主页＋在线简历**：具有独立页面结构、作品/经历模块和公开站点体验时收录；只有简历文件预览或下载时排除。
- **个人主页＋服务展示**：明确以个人或自由职业者为主体可收录；以公司、工作室或团队品牌为主体则按企业官网排除。
- **学术主页＋博客/出版物**：研究者身份、研究方向、论文或项目构成主体时收录；只聚合文章链接时排除。

### 4. 明确排除

企业官网、公司产品官网、纯博客站、纯 Link-in-bio 页面、只有一张电子名片的页面、招聘平台个人主页、Notion 公开页、无独立作品形态的社交主页、纯简历 PDF、无法公开访问的作品，以及无法确认 AI 辅助开发的公开候选，不进入首期正式作品库。

## 九、数据资产与两层模型

VibeCheck 的通用主对象与首期品类字段必须分离。

| 层级 | 保存内容 | 扩品类规则 |
| --- | --- | --- |
| `ProjectCore` | 名称、作者、URL、历史地址、截图、仓库、开发工具、技术栈、部署、状态、生命周期、资产、关系、证据、审核状态 | 所有 Vibe Coding 品类共享，禁止加入 Portfolio 专属字段 |
| `PortfolioSchemaV1` | 网站类型、作者身份、用途、页面结构、内容模块、项目展示、视觉风格、布局、主题、交互、响应式和博客能力 | 通过 `category_id`、`category_schema_version`、`category_data` 挂载，可独立演进 |
| 派生数据 | 策展子群、匹配原因、完整度、时效、是否开源/可 Fork、资产数量 | 由通用字段和 Category Schema 计算，不作为重复事实保存 |

每条关键事实记录证据来源和最后验证时间。公开观测、已验证作者声明、可信外部来源与系统推断分开保存；未知、过期和争议信息必须明确表达。

## 十、产品形态

VibeCheck 继续采用“社区前台＋结构化作品档案内核”的形态，保留作品广场、分类/专题、最新动态、全局搜索、查同类、作品详情、比较、发布、作者主页、个人中心和运营后台。

社区浏览以真实截图为第一信息层，作品类型、作者身份、视觉风格、核心模块、开源/模板状态等结构化信息负责解释、筛选和比较。点赞和评论用于社区反馈，但不得覆盖匹配度、证据、时效与复用价值。

## 十一、供给与冷启动

首期正式种子库目标为 **64 个** 高质量作品档案，覆盖 8 个策展子群，每群至少 6 个作品。额外配额优先分配给质量、差异性和复用价值更高的作品，不以凑满单一标签数量为目标。

种子库同时满足：

- 至少 24 个作品公开源码或提供直接 Fork/Clone 入口；
- 至少 32 个作品包含一种以上可复用资产；
- 单一技术栈或单一 AI Coding 工具占比不超过 40%；
- 同时覆盖单页、多页和混合结构，浅层项目展示与深度 Case Study；
- 同时覆盖浅交互、中等交互和高交互作品，不以高动画等同高质量；
- 公开状态、来源和核心字段达到统一核验标准。

供给采用平台编辑建档、公开页面发现、作者主动发布和用户线索补充并行。已有档案的作者身份关联继续作为低频归属与编辑权限流程，不作为主要供给路径。

## 十二、可信、排序与边界

作品排序优先考虑查询匹配度、视觉与结构可比较性、数据完整度、证据强度、最近验证时间、资产可用性和编辑策展。新鲜度与社区互动只能作为弱信号。

作者是否付费、是否频繁更新、是否与平台合作，不得直接决定自然排序。赞助内容必须与自然结果分离。

页面可访问、仓库更新、作品被收藏或获得大量 Fork，均不直接等同于职业能力、商业成功或真实采用。关系与复用行为需要区分用户意向、单方声明、双方确认和平台核验。

## 十三、首期 MVP 战略重点

首期需要验证五个命题：

1. 强视觉作品供给能否形成稳定的浏览和收藏行为；
2. 结构化字段能否把“喜欢”转化为网站类型、结构、视觉和实现选择；
3. 比较与复用入口能否推动用户开始或调整开发；
4. 使用过平台的创作者完成网站后是否愿意发布回流；
5. 新作品是否愿意引用参考、模板或组件，从而形成真实作品关系。

“暂停开发”仍被保留为通用行为，但不再作为首期主要价值表达。首页、详情和比较应重点推动获取灵感、收藏参考、确定结构、选择方向、复用资产、开始开发和发布作品。

## 十四、指标体系

### 1. 北极星指标

首期北极星指标为：**每周完成有效作品发现并产生创作推进动作的创作者数。**

有效作品发现要求用户深度查看至少一个作品详情或完成一次同类结果浏览；创作推进动作包括收藏参考、开始比较、完成比较、访问源码/Fork/模板、保存开发行动、发布作品或发布更新。点赞、评论和分享单独发生时不计入。

### 2. 核心配套指标

| 指标 | 定义 |
| --- | --- |
| 详情深访率 | 进入详情后查看至少一个结构化档案模块、资产或关系的会话比例 |
| 收藏参考率 | 深度访问后收藏作品作为参考的用户比例 |
| 比较发起/完成率 | 选择 2—5 个作品并进入/完成核心维度浏览的比例 |
| 可复用资产点击率 | 深度访问或比较会话中打开资产详情或外部获取入口的比例 |
| Fork/模板使用意向 | 点击 Fork、Clone、Use template 或记录复用行动的用户比例 |
| 比较后开发行为 | 完成比较后保存“开始开发、调整方向或复用资产”的比例 |
| 60 天新作品回流率 | 发生有效发现的创作者在 60 天内发布新作品的比例 |
| 新作品引用旧作品比例 | 新发布作品声明参考、模板、组件或代码关系的比例 |
| 作品更新率 | 已发布作品在观察期内产生有效版本、资产或状态更新的比例 |
| 数据完整与时效 | P0 字段完整度、证据覆盖率和最近 30 天状态有效率 |

行为指标上线后先建立四周基线，再按渠道和用户状态设定增长阈值；数据质量和冷启动密度属于上线前硬门槛。

## 十五、长期壁垒与阶段演进

VibeCheck 的长期壁垒由四项资产构成：跨平台作品身份、连续生命周期历史、可扩展 Category Schema，以及真实参考与复用关系。

| 阶段 | 核心目标 | 进入下一阶段的条件 |
| --- | --- | --- |
| 一：单类别闭环 | 验证浏览、收藏、比较、复用、发布与关系回流 | 创作推进动作和新作品回流成立 |
| 二：作者与关系服务 | 提高作者更新、资产供给和关系确认 | 作者持续更新且关系数据可维护 |
| 三：相邻类别扩张 | 复用 `ProjectCore` 并增加新的 Category Schema | Portfolio 数据密度与流程稳定 |
| 四：跨品类作品网络 | 建立跨平台身份、生命周期和复用图谱 | 数据规模、准确率与历史跨度形成壁垒 |

品类扩张不得通过向 `ProjectCore` 追加首期专属字段完成。新类别必须使用独立 Schema，并复用作品身份、作者、状态、事件、资产、关系和证据等通用能力。

## 十六、最终定位陈述

面向使用 AI 编程工具开发数字产品的个人创作者和小型团队，VibeCheck 是一个作品发现、发布与生命周期资产平台。

首期，创作者可以浏览和比较个人主页与作品集网站，从真实截图进入结构、项目展示、视觉交互、技术实现和可复用资产，形成保存参考、开始开发、调整方向或复用现有成果的行动。完成开发后，创作者可以发布作品、声明参考与复用关系，并持续记录网站改版、项目新增、资产开放和访问状态。

“个人主页与作品集”是首期数据切口，不是 VibeCheck 的长期产品边界。长期，VibeCheck 将扩展到更多 Vibe Coding 作品类型，形成跨平台的作品身份、生命周期事实、Category Schema 与复用关系网络。
