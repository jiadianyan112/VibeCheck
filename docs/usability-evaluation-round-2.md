# 第二轮低保真原型可用性评测

## 目的与判定原则

本轮验证 VibeCheck 是否能让创作者独立完成会改变下一步开发行为的任务。评价依据是任务结果，不是受访者对社区页面、视觉风格或概念的主观好感。

本轮不收集或声称收集真实生产数据。原型中的账号、作品、链接与审核结果均为固定模拟数据；主持人只记录受访者的操作和经同意的录屏。

## 招募

招募 6 人，另设 2 位候补，保持在题设要求的 5—8 人范围内。不要用项目成员、直接参与原型设计的人或只做一般内容浏览的人替代目标用户。

| 配额 | 入选条件 | 分配任务 |
| --- | --- | --- |
| 3 名准备开发者 | 未来 30 天内准备或正在开发一项 AI 学习、题库或相近 Web 工具；已用过至少一种 AI 编程工具 | A：发现、比较、复用和开发决策 |
| 1 名已发布作者 | 曾公开发布过一个可访问的 Web 作品，并仍可提供作品地址 | B1：发布新作品 |
| 2 名已发布作者 | 曾公开发布过一个 Web 作品，且有过维护、更新或作品归属管理经验 | B2：发现已有档案后认领 |

筛选时记录其最近开发/发布作品的类型与所用工具，避免收集作品源码、账号密码、私密链接或客户信息。若某人同时符合两类，按配额缺口分配一次任务，不让同一个人完成两类主任务。

## 会前准备

1. 在独立浏览器配置文件或无痕窗口启动原型：`npm run dev -- --host 127.0.0.1 --port 4173`。
2. 每位受访者开始前清理站点数据，或在开发模式左下角“原型场景”中点击“重置场景与原型数据”。不要让前一位的登录、比较和草稿遗留给下一位。
3. 使用桌面浏览器、1366 × 768 或相近视口；记录实际设备、浏览器和是否使用键盘/辅助技术。若要测移动端，另行作为独立批次，不能把结果与本轮合并。
4. 仅在取得许可后录屏和录音。录屏中若出现受访者的真实作品或个人资料，应在归档前裁切或打码。

建议每场 35 分钟：3 分钟说明、20 分钟主任务、5 分钟回顾关键停顿、7 分钟缓冲和记录。主持人可请对方自然说出想法，但不得解释字段、指出入口或替其点击。

## 主持人口径

开场白：

> 这是原型，不是对你的测试。请像平时一样操作，遇到不确定的地方可以说出来。除非你明确表示放弃或请求帮助，我不会提示下一步。我们关注你是否能完成任务，而不是你是否喜欢页面。

任务开始时开始计时。仅在受访者明确放弃、15 分钟到时，或操作会泄露真实敏感信息时停止。必要帮助后仍可完成的任务单独标为“完成但需协助”，不能计入独立完成。

## 任务 A：准备开发者

起点：`http://127.0.0.1:4173/projects`，未登录、状态已重置。

向受访者逐项读出以下情境，不给出页面名称、关键词或作品名：

1. “你计划做一个能把 PDF 学习材料自动变成练习题的工具。请找出三个最接近的已有作品。”
2. “从刚才的结果中，选两个你会重点研究的作品，比较它们，并找出可直接复用的源码。请说出它的许可和当前可用性。”
3. “现在请基于比较结果，做出你下一步是继续、调整、复用还是暂停的决定，并把这个决定和理由保存下来。”

任务 A 的完成标准：

| 子任务 | 独立成功的可观察结果 |
| --- | --- |
| A1 找同类 | 找到并能指出“题练工坊”“PDF 题库实验室”“Paper to Practice”三个作品。 |
| A2 比较与复用 | 将至少两个 PDF 题目生成作品放入同一比较会话，查看结构化差异和“可复用资产”，定位“题练工坊基础源码”，并准确说出 `MIT` 与“可用”。 |
| A3 作出行动 | 在“记录比较后的行动”中选择一个行动、至少一个受影响字段和理由，关联资产（若其决定是复用），最终看到“决策记录已保存”。 |

主持人不得要求某一种具体决策。受访者选择继续、调整、复用或暂停都可通过，前提是独立保存了和比较结果一致的行动；“只是浏览完”不算完成。

## 任务 B：已发布作者

### B1 发布新作品

起点：使用固定身份“米娅”登录后打开 `http://127.0.0.1:4173/submit`。为避免私密数据，将下列演示地址和产品事实印在任务卡上：

```text
地址：https://example.test/revision-pdf-practice
作品：PDF 复习小助手
目标用户：大学生
核心问题：把 PDF 学习材料快速转成可复习的练习
使用场景：生成题目
主要输入：PDF
主要输出：题目
核心流程：上传材料 / 生成练习 / 查看反馈
```

任务： “请像发布自己新作品一样，检查这个地址、完成必要信息并提交审核。你只需提交到审核，不需要等待真实人工审核。”

独立成功：完成地址检查、四步必填信息与预览确认，提交审核后能明确指出审核状态。记录是否理解可跳过字段、自动保存、审核前后边界。

### B2 发现已有档案后认领

起点：使用固定身份“周可”登录后打开 `http://127.0.0.1:4173/submit?scenario=duplicate_project`。任务卡给出地址 `https://example.test/u05-existing-project` 和两段模拟材料：

```text
材料摘要：公开主页展示了本人身份与该作品名称。
验证材料：https://example.test/private/u05-proof
```

任务： “你想发布这个作品，但平台可能已经收录了它。请在不重复创建档案的前提下，争取获得管理这个作品的权限。”

独立成功：识别“已有作品档案”，不继续创建新作品，主动选择作者身份验证，提交两项必填材料，并看到“待人工审核”。成功后能说出材料不会公开展示且尚未获得编辑权限。把误选“继续发布”、忽略重复提示或把隐私材料误认为公开字段记录为关键问题。

## 记录表与编码

每项子任务各占一行；不要事后仅凭记忆补录。`P` 是受访者编号，`A/B1/B2` 是任务编号。

| P | 人群/工具经验 | 任务 | 结果：独立完成／协助完成／失败 | 开始—结束/秒 | 首次停顿位置与时长 | 错误点击或回退 | 不理解的字段（原话） | 被忽略的关键信息 | 最终行动/状态 | 证据时间戳 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| P01 | 准备开发者；Cursor | A1 |  |  |  |  |  |  |  |  |
| P01 | 准备开发者；Cursor | A2 |  |  |  |  |  |  |  |  |
| P01 | 准备开发者；Cursor | A3 |  |  |  |  |  |  |  |  |

统一编码规则：

- **完成率**：独立完成数 ÷ 被分配该任务的人数；“协助完成”和“失败”分别报告，不合并为完成。
- **完成时间**：从读完任务到看到成功结果或宣布停止。报告中位数、范围和每位原始秒数，不用小样本均值掩盖极端值。
- **停顿**：连续 5 秒没有可推进操作，且出现犹豫、反复阅读、询问含义或来回滚动。记录界面区域和原话；单纯阅读长文本不自动算停顿。
- **错误点击**：与当前目标无关、产生意外状态、或点击后立即撤销/返回的操作。不要把探索性点击一律视为错误。
- **无法理解的字段**：受访者明确问含义、作出错误解释，或填写值与字段定义明显不符；保留其原话。
- **被忽略的信息**：对完成或安全判断必需的信息已进入可见区域，但受访者未采纳，且后续行动与该信息矛盾。不得仅因未朗读某段文字就标记为忽略。
- **最终行动**：任务 A 记录实际保存的继续/调整/复用/暂停；任务 B 记录审核提交、重复创建尝试或放弃。它是本轮的主要行为结果。

## 观察重点与判定阈值

本轮样本用于发现可用性风险，不用于推断总体比例。以下阈值只用于决定是否在下一版前修复：

| 信号 | 处理优先级 |
| --- | --- |
| 同一主任务有 2 人无法独立完成，或任何人因重复发布/隐私理解错误做出高风险行动 | P0，下一轮前先修复并回测 |
| 1 人被主路径阻断，或 2 人在同一入口、字段或状态上停顿/错误点击 | P1，进入下一版修复清单 |
| 1 人短暂停顿但能自行恢复，或只是措辞偏好 | P2，结合后续证据决定 |

期望的最低行为信号是：每类主任务至少 2/3 人独立完成，且没有人因不理解“已有档案”“验证材料私有”“当前状态”或“复用资产”而做出相反行动。若达不到，不以“大家觉得页面有价值”抵消该问题。

## 回顾问题与输出

任务结束后，只针对刚出现的行为追问：

1. “刚才你在这里停住时，原本在找什么？”
2. “你认为这个字段/状态会带来什么结果？”
3. “是什么信息让你决定继续、调整、复用、暂停、发布或认领？”

不要问“你喜不喜欢社区页面”或让受访者设计解决方案。主持人可在会后把观察归并为“发现、比较、资产、决策、发布、认领”六类，按优先级写出：问题、证据（P 编号和时间戳）、受影响任务、建议变更、回测任务。所有结论必须可回到一次具体的独立操作或未完成操作。
