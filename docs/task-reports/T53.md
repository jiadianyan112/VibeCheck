# T53 建立原型场景切换与异常矩阵

## 实施摘要

以统一 `prototypeScenario` 参数和开发环境 `ScenarioPanel` 替换散落的临时开关，覆盖任务书要求的 11 个非理想状态。面板切换前会重置本地原型数据，并按场景建立固定身份、草稿或比较选择；生产构建隐藏面板但保留 URL 场景参数。

## 主要改动

- `src/mocks/scenario.ts`：统一场景目录、分组、固定路径及到历史服务场景的兼容映射。
- `src/components/ScenarioPanel.tsx`：开发环境场景面板、一键准备、切换隔离和完整重置；替换旧 `PrototypeDebugPanel`。
- 前后台布局：只在 `import.meta.env.DEV` 为真时挂载场景面板，并确保面板处于路由上下文内。
- 搜索、比较、发布、提取、审核、身份和更新页面：统一解析 `prototypeScenario`，同时保留既有 `scenario` 回归别名。
- 发布重复与外链风险：固定 URL 使用 `autoCheck=1`，进入后自动完成检查，且不创建草稿。
- `docs/scenario-matrix.md`：记录 11 个场景的唯一索引、固定 URL、准备数据、预期结果和隔离规则。
- `e2e/scenario-matrix.spec.ts`：验证生产构建隐藏面板但参数仍生效，并验证 URL 场景不会污染后续默认搜索。
