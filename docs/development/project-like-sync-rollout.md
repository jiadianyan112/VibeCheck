# 点赞跨设备同步

## 数据与刷新

点赞使用现有 `community.project_interactions` 和 `catalog.project_interaction_counters`。写入复用已有带 CSRF、来源检查和幂等凭据的最终状态接口；账号状态通过 `GET /api/v1/interactions/projects?project_ids=...` 批量读取，响应不可缓存，最多请求100个公开作品。

网页登录后以服务端数量为准，不再额外加一本地点赞。进入页面、窗口恢复焦点、页面重新可见时刷新，停留期间每30秒同步。保存失败保留最后确认结果，按钮支持重试；切换账号清除先前账号快照。旧浏览器模拟点赞不自动导入数据库。

## 部署

本次没有新数据库迁移。构建并部署 `codex/actual-experiences` 最新提交到 `vibecheck-web`（包含 API 和网页）。保持已有 `COMMUNITY_ENABLED=true` 和社区密钥配置。

## 线上验收

1. 设备 A 登录账号并在作品广场点赞，数量增加一次。
2. 设备 B 登录同一账号，打开相同作品，显示已点赞和同样的服务端总数。
3. 设备 B 取消点赞，设备 A 切回窗口或等待30秒，恢复未点赞状态和正确数量。
4. 换另一账号，显示该账号自己的点赞状态；刷新、重新登录后仍保留。
5. 网络失败时不会虚增数量，重试同一最终状态不会重复累计。

本地测试覆盖客户端接线、账号切换、另一设备恢复、窗口刷新和失败保存。真实 PostgreSQL fixture 与生产两设备验收需要可用数据库和部署环境；本地模拟通过不代表线上已验收。
