# 收藏、关注与更新通知上线

日期：2026-10-03。分支：`codex/account-favorites-follow-sync`。

## 交付范围

- 详情收藏与关注读取账号数据库状态，写入最终状态并应用服务端返回的完整联动结果和绝对计数。
- 个人中心通过 `GET /api/v1/interactions/favorites` 分页读取当前账号公开作品收藏；游标签名绑定账号，禁止其他账号复用。
- 收藏、关注、点赞保持独立；关注会收藏，取消收藏会取消关注，单独取消关注保留收藏。
- 页面在获得焦点、恢复可见和可见时每 30 秒刷新。失败保留已确认结果；切换账号丢弃旧请求。
- 作品更新通知按 `catalog.events.created_at` 时点的关注历史选择收件人，保持现有每个作品更新/收件人的去重键。禁用或删除中的账号和不公开作品不参与通知。
- 通知跳转到具体作品时间线事件；时间线读取真实公开接口。未读、已读状态来自服务器，并防止迟到读取覆盖已读写入。
- 作者自己的作品发布通知继续独立发送站内消息，不依赖关注，也不发送成功邮件。

## 迁移与历史边界

新增 `000047_project_follow_history.sql`：关注历史表、自动记录变化的触发器、收藏分页索引。触发器随互动事务提交，不记录没有状态变化的更新。

迁移前已丢失的关注变化不能完整重建。迁移只保存每条已有关注记录最后确认的状态及更新时间；新变化开始完整记录。不要据此补发未知历史状态下的通知。

## 部署顺序

1. Northflank 的 `vibecheck-db-migrate` 构建来源切换到本分支，构建并部署本阶段提交。
2. 手动运行迁移任务，确认 `migrations_ok` 与退出码 `0`。若此前已应用到 46，此次应为 `applied=1 existing=46`；再次运行应为 `applied=0 existing=47`。
3. 迁移成功后，将 `vibecheck-web` 与 `vibecheck-worker` 切换到同一分支和提交，构建并部署，确认两项服务 Running。
4. 保留已有 `COMMUNITY_ENABLED`、游标密钥和举报加密配置。本阶段没有新的环境变量，也不需要更换密钥。
5. 用两设备进行下列验收。

## 线上验收

- 同账号 A 收藏，B 在刷新/恢复页面后看见；取消后两边消失。刷新和重新登录保留数据库结果。另一账号看不到该收藏。
- A 关注后同时收藏；取消收藏同时取消关注；单独取消关注保留收藏。详情和个人中心状态相同，计数没有额外加一。
- 关注后发布作品更新：作者审核发布通知正常，关注者收到一条更新通知；重复消费不重复通知。
- 消费延迟时，事件发生后才关注的用户不收到旧事件；事件发生时关注、随后取消的用户仍可收到当时应收到的事件。取消后的新事件不再送达。
- 点击通知定位到该更新；A 标已读，B 刷新/恢复页面后未读数和已读状态同步。
- 隐藏作品不能通过收藏列表读取；请求失败保留已确认状态，可重试；快速点击、切换账号和迟到响应不串号。
- 补验上一阶段点赞在真实数据库和两设备上的同步，不能用模拟测试代替。
