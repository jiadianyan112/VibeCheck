## 1. 产品定义

VibeCheck 是一个 Vibe Coding 作品社区。首期聚焦 AI 学习、练习和题库类 Web 作品，帮助使用 Cursor、Lovable、Bolt、v0、Replit、Claude Code、Codex 等工具的创作者：

1. 发现同类作品、创作者和 Vibe Coding 工具；
2. 看懂作品解决的问题、核心流程、开发方式与当前状态；
3. 对 2—5 个作品进行结构化比较，并记录下一步行动；
4. 复用公开代码、模板、组件、提示词或方案；
5. 发布、认领并持续更新自己的作品档案。

平台提供可追溯的作品事实，不根据作品数量、访问状态或互动量推断市场需求、竞争强度、收入、活跃度或商业成败。

## 2. MVP 目标与成功指标

### 2.1 产品目标

- 让准备开发的用户能从一个产品想法出发，独立找到同类作品并完成一次有效比较。
- 让已发布作者能完成新作品发布，或在发现已有档案时避免重复发布并申请认领。
- 让已验证作者能发布一次留痕更新，并触达关注该作品的用户。
- 建立同一个 `projectId` 贯穿发现、详情、比较、收藏、动态、作者、发布和后台的稳定档案体系。

### 2.2 首期核心指标

| 指标 | 计算口径 | MVP 观察目标 |
| --- | --- | --- |
| 有效发现率 | 进入搜索/想法分析的会话中，最终打开作品详情或加入比较的会话占比 | 上线后建立基线，连续观察 4 周 |
| 有效比较完成率 | 选择至少 2 个作品并保存“继续/调整/复用/暂停”行动的比较会话占比 | 上线后建立基线，优先于页面浏览量 |
| 资产行动率 | 完成比较的会话中，打开至少一个可复用资产的会话占比 | 上线后建立基线 |
| 发布分流正确率 | 发布地址查重命中后，没有新建重复档案并进入详情/认领/纠错的提交占比 | 100% 不允许绕过查重直接新建 |
| 作者维护回流率 | 已验证作者在作品发布或认领后 30 天内至少更新一次档案的占比 | 上线后建立基线 |
| 更新触达率 | 作品更新通知中，被关注者打开并定位到对应事件的占比 | 上线后建立基线 |

浏览量、收藏量、点赞量和作品总数仅作为诊断指标，不作为首期成功结论。

## 3. MVP 范围

### 3.1 本期必须交付

- 公开作品广场、分类、动态、统一搜索、完整想法分析、作品详情和作者主页。
- 2—5 个作品的临时/已保存比较、结构化差异、复用资产和私密行动记录。
- 登录、收藏、个人中心内关注更新、最近浏览、通知和讨论。
- 发布地址检查、查重分流、自动预填、分步编辑、提交审核和审核状态。
- 已有作品认领、私有材料审核、作者管理权限。
- 已验证作者发布版本、地址、状态、说明和复用资产更新。
- 运营后台的作品队列、作品编辑、证据复核、发布审核、身份审核、重复合并、状态监测和一致性检查。
- 统一的加载、空、无结果、无权限、冲突、网络失败、服务失败和外链风险处理。

### 3.2 本期不做

- 泛 Vibe Coding 全品类扩张；首期仅运营 AI 学习与练习工具。
- 娱乐榜单、粉丝排行、私信、群聊、直播或泛内容信息流。
- 收入、用户规模、融资、市场空间、竞争强度等未经核验的商业判断。
- 付费资产交易、平台抽佣、订阅或支付。
- 原生移动 App；仅交付响应式 Web。
- 自动将 HTTP 异常推断为暂停、结束或失败。
- 自动替作者发布终止性声明。
- 多人实时协作编辑、团队空间和组织级权限。
- 基于用户画像的黑箱个性化排序；首期排序必须可解释。

规则：

- 所有权限必须在服务端校验，前端隐藏或禁用按钮不能代替权限控制。
- 登录回跳必须携带安全的站内 `from` 路径；禁止 `//`、外域或脚本协议。
- 游客触发收藏、点赞、评论、保存比较、保存行动或发布时，登录后只回放最近一次明确操作一次。
- 登录时保留游客刚选择的比较作品，不自动把账户历史比较作品合并进当前会话。
- 作者身份验证只改变作者关联与管理权限，不新建作品、不改变作品数量、不删除历史。
- 归属争议期间冻结地址、状态、历史等高风险编辑，公开档案和已有历史继续展示。

## 5. 全局业务规则

### 5.1 作品稳定身份

- 每个作品只有一个全局唯一且不可复用的 `projectId`。
- 卡片、详情、收藏、关注、评论、比较、动态、资产、作者关系、审核和通知均引用同一 `projectId`。
- 重复作品合并后保留主档 `projectId`；副档转为归档并建立永久别名。旧链接自动跳转主档，收藏、关注、比较、通知和草稿引用同步迁移。
- 已发布或进入审核的对象不得物理删除；后台使用归档、撤回、限制展示和别名映射。

### 5.2 事实、状态与来源

作品关键字段使用“已知/未知”事实结构：

```text
state: known | unknown
value: 已知时必填
reason: 未知时必填
evidenceIds: 来源 ID 列表
freshness: valid | expiring | expired
lastVerifiedAt: 最近验证时间，可空
disputeStatus: none | in_review | resolved | insufficient_evidence
confidence: high | medium | low | null
```

- 未知字段必须显示“未知”和原因，不得用生成摘要、默认值或其他作品信息补写。
- 过期信息继续展示原值与最后验证时间，并明确提示可能已变化。
- 争议信息并列展示来源；争议解决前不得选择性覆盖。
- `accessStatus` 表示公开作品当前状态；`httpCheckStatus` 仅表示技术观测，两者不得混用。
- 技术检查可以产生正常、重定向、超时、DNS、证书、拦截或未知信号，但不能直接产生暂停、结束或失败结论。
- 生命周期事件只能追加，必须记录时间、来源、前值、后值和争议状态；当前字段变化不得删除历史事件。

### 5.3 前台作品卡片

所有发现作品场景统一展示：

1. 作品名称；
2. 一句话介绍；
3. 作者，已验证作者显示验证标记；无作者显示“待认领/待补充”；
4. 最多 2 个 Vibe Coding 工具，更多显示 `+N`；
5. 当前可访问状态；
6. 场景需要时提供收藏和加入比较。

首页、分类、搜索和相关推荐卡片不展示资料完整度、核验日期或来源数量；完整度、核验状态、来源和证据只在详情、比较或后台展示。收藏按钮点击后直接切换“收藏/取消收藏”，不得弹出关注设置。

### 5.4 收藏与关注更新

- 收藏是一级动作；关注更新是收藏下的附属状态。
- 收藏成功后作品进入个人中心“收藏”。
- “关注更新/取消关注更新”只在个人中心的收藏列表中出现。
- 关注更新时若作品尚未收藏，服务端应先收藏再关注；正常 UI 不提供此越级入口。
- 取消关注不取消收藏；取消收藏必须同时取消该作品的关注更新。
- 重复点击使用幂等写入，以最终布尔状态为准，不得重复累计互动数。
- 作品发布新版本、状态、地址、说明或资产更新后，仅给仍处于关注状态的用户生成一条去重通知。

### 5.5 比较会话

- 比较下限 2 个、上限 5 个作品；加入重复作品不产生变化，超过 5 个时拒绝并提示先移除或替换。
- 游客比较属于当前浏览器的临时会话；刷新和站内跳转不丢失，默认保留 7 天。
- 登录后当前游客会话归属当前账户并可保存；账户历史会话不得自动并入当前选择。
- 比较页默认直接定位“结构化比较”；作品管理折叠在顶部工具栏，少于 2 个作品时自动展开。
- 桌面端按作品列横向比较；移动端按作品切换，不以缩小表格方式适配。
- 悬浮比较栏默认只显示“已选 N 个、清空、开始比较”；作品列表由用户展开。
- 已删除/归档作品在旧会话中保留位置并显示不可用，可替换或移除，不能静默丢失。
- 行动记录必须关联一次比较会话，包含行动、受影响字段、理由和可选资产；可见性固定为仅本人。

### 5.6 统一搜索入口

- 桌面端使用顶部统一搜索；移动端通过菜单进入同一搜索能力。页面不再存在独立“查同类”主导航。
- 输入先执行 `trim` 并合并连续空白；空输入进入普通搜索页。
- 满足以下任一条件自动进入完整想法分析：
  - 标准化文本长度不少于 24 个字符；
  - 长度不少于 10 个字符，且包含“我想/我需要/希望/帮我/做一个/开发一个/创建一个/实现一个/用于/面向/能够/可以/把…生成/转换/变成”等意图表达。
- 其他输入进入普通关键词搜索。
- 自动分流后用户始终可以切换为“按关键词搜索”或返回修改想法。
- 输入最大 500 个 Unicode 字符；超过时在输入框下提示并禁止提交。埋点不记录完整长文本，只记录长度、哈希和解析标签。

### 5.7 上下文恢复

- 搜索词、筛选、排序、结果视图和比较会话 ID 保存在 URL 中，可刷新、返回和分享。
- 列表进入详情再返回时恢复筛选、排序和滚动位置。
- 发布、身份验证和作品更新表单自动保存服务端草稿；网络失败、权限失效或刷新后恢复最近一次成功保存内容。
- 提交审核时冻结不可变提交快照；之后编辑草稿不能改写已提交版本。

### 5.8 外链安全

- 作品体验地址、代码仓库、资产和作者联系方式均通过外链确认层打开。
- 只允许 `http` 和 `https`；禁止 `javascript:`、`data:`、`file:`、内网 IP、localhost 和无法解析域名。
- 打开新窗口时使用 `noopener,noreferrer`。风险检测失败时阻止跳转并提供取消、复制地址或报告问题。
- 发布地址探测必须防止 SSRF，不允许服务端访问私有网段、云元数据地址或重定向后的私有目标。

## 7. 前台页面需求

### P01 作品广场

**功能**

- 首屏明确“Vibe Coding 作品社区”，说明首期聚焦 AI 学习与练习工具。
- 提供统一搜索、快捷问题、探索作品和发布作品入口。
- 依次展示：编辑精选、最新发布、最近更新、开源可复用、按问题探索、已结束但仍可复用。
- 标准卡片展示收藏和加入比较；紧凑卡片至少支持加入比较，是否展示收藏由所在区块统一决定。

**排序**

- 编辑精选：`editorial_rank ASC`，仅公开、资料完整且未限制展示，最多 3 个。
- 最新发布：`firstPublishedAt DESC, projectId ASC`，最多 4 个。
- 最近更新：最近公开生命周期事件 `happenedAt DESC, eventId ASC`，无事件时使用 `lastVerifiedAt`，最多 4 个。
- 开源可复用：至少一项未移除资产，优先 `assetAvailability=available`、最近核验、`projectId`，最多 4 个。
- 已结束但仍可复用：`accessStatus=ended` 且有可用资产，按资产最近核验时间倒序。

**状态与异常**

- 加载使用骨架或状态提示；服务失败保留页面入口并提供重试。
- 某区块为空时只显示该区块空状态，不影响其他区块。
- 首页接口部分失败时允许成功区块先展示，并对失败区块单独重试。

### P02 分类总览

**功能**

- 分类围绕“学习问题—练习场景—反馈闭环”组织，技术栈只作为辅助标签。
- 每个分类展示问题描述、范围边界、作品数、代表作品、主要解决路径、最近事件和最多 2 个常用构建工具。
- 分类目录由运营配置，`slug` 唯一且不可随意复用。

**排序**

- 分类按后台配置 `display_order ASC`；作品数不决定顺序。
- 代表作品使用第 10 章定义的代表作规则；最近事件按时间倒序取 1 条。
- 常用工具按该分类公开作品使用次数倒序，同数按工具枚举顺序。

### P03 分类/专题详情

**功能**

- 展示专题说明、解决路径、代表作品、可筛选作品流、最近 4 条更新和全部公开复用资产。
- 筛选项：目标用户、材料输入、练习形式、反馈方式、当前状态、有公开源码、有复用资产。
- 排序项：最近核验、名称、资料完整度。筛选和排序写入 URL。
- 返回页面恢复滚动位置；无结果时可一键重置筛选。

**排序**

- 默认 `lastVerifiedAt DESC, projectId ASC`。
- 名称按中文本地化排序，未知名称置后，再按 `projectId`。
- 完整度顺序：完整、部分完整、资料有限、等待核验、争议；同级按最近核验倒序。
- 复用资产默认按可用状态、最近核验时间、资产 ID 排序。

**异常**

- 无效 `slug` 返回专题不存在页并提供分类总览入口，HTTP 状态为 404。
- URL 中非法枚举参数忽略并上报诊断事件，不导致页面崩溃。

### P04 最新动态

**功能**

- 只展示有事实意义的公开事件：首次发布、版本更新、地址迁移、产品调整、链接异常/恢复、暂停、结束、资产新增和被复用。
- 支持事件类型和学习分类筛选；点击事件定位到详情时间线锚点。
- 事件展示作品、事件类型、时间、摘要、争议状态和事件来源入口。

**排序与可见性**

- `happenedAt DESC, eventId ASC`；估算日期必须显示“约”。
- 限制展示作品的事件不进入公共流；归档副档事件通过别名归并到主档。
- 系统推断事件明确标记，不与平台核验或作者声明混淆。

### P05 统一搜索结果

**功能**

- 关键词模式支持名称、定义、核心问题、使用场景、材料输入、练习形式和常用中文别名召回。
- 每条结果展示“为什么匹配”的字段标签。
- 筛选项：目标用户、材料输入、当前状态、复用资产；排序项：匹配程度、最近核验、名称。
- 完整想法自动跳转 P06；用户可显式强制按关键词搜索。

**排序**

- 相关性：`text_score DESC`，再按结构化字段命中数、`lastVerifiedAt DESC`、`projectId ASC`。
- 最近核验：`lastVerifiedAt DESC, relevance DESC, projectId ASC`。
- 名称：本地化名称升序，未知置后，`projectId ASC`。

**异常**

- 无结果保留原查询和筛选，提供清空条件、修改查询和发布作品入口。
- 搜索服务超时保留输入，提供重试；不得自动清空或跳首页。
- 结果只包含公开且未限制展示作品。

### P06 完整想法确认

**功能**

- 保留原始想法，解析为目标用户、使用场景、主要输入、练习形式和主要输出。
- 每个维度可添加、删除标签；至少一个维度非空才能继续。
- 展示解析完整度：信息较完整、建议核对、需要补充；不得把低置信度结果伪装为确定答案。
- 用户可以修改原始想法重新解析、撤销标签修改或改看关键词结果。

**状态**

- `idle → parsing → success|partial|failed`。
- 解析失败时保留原文，允许手动补标签或进入关键词搜索。
- 同一原文的未确认标签草稿在当前会话中保留；确认后生成可分享的结果 URL。

### P07 想法匹配分析

**功能**

- 分为“作品结果”和“同类分析”两个视图。
- 作品结果区分精确匹配和相近推荐；精确结果少于 3 个时显示最多 4 个相近作品；精确结果为 0 时提供相关专题、修改条件和保存查询。
- 同类分析展示代表作品、常见做法分组、作品状态分布和可复用内容分布。点击统计项返回过滤后的作品结果。
- 卡片支持加入比较；分析页不输出市场需求或商业机会结论。

**匹配与排序**

- 精确匹配：用户已选择的每个非空维度均至少命中一个值；空维度不参与约束。
- 相近推荐：按命中维度数倒序、最近核验时间倒序、`projectId` 升序，最多 4 个。
- 常见做法按“首个使用场景 + 首个输入 + 首个练习形式”分组，按组内作品数倒序、组 ID 升序。
- 相邻专题得分：场景命中 +3，PDF 必需且输入命中 +1；按得分倒序、`slug` 升序，最多 3 个。

### P08 作品详情

**功能区域**

1. 作品媒体、名称、定义、当前状态、作者与档案来源；
2. 立即体验、直接收藏/取消收藏、分享、加入/移出比较；
3. 收藏、点赞、讨论计数；
4. 作品信息与状态、来源、核验时间、完整度和争议提示；
5. 产品结构：用户、问题、场景、输入、输出、功能、登录、分享、核心流程；
6. 开发信息：Vibe Coding 工具、模型、技术栈、部署、周期和依赖；
7. 当前状态、复用资产、作品时间线、相关作品和讨论；
8. 作者认领、已验证作者管理和公开纠错入口。

**交互规则**

- 收藏点击后直接切换，不显示关注弹窗。
- 点赞、收藏和评论要求登录；登录后回放一次。
- 分享优先调用 Web Share API，失败时复制规范链接，再失败提示从地址栏复制。
- 立即体验经过外链安全确认；地址未知或作品限制展示时禁用。
- 评论类别为使用反馈、开发问题、复用反馈、状态补充；支持一级回复和举报。
- 评论正文 `trim` 后 1—1000 字符；只含空白、超长或命中明确恶意载荷时禁止提交。
- 举报不物理删除评论；进入审核中，可折叠或隐藏并保留审核历史。

**状态与异常**

- 旧 `projectId` 自动跳转合并主档并提示已合并。
- 未找到作品返回 404；限制展示返回受限页但保留允许公开的历史说明。
- 暂停、结束、异常、迁移、未知、过期和争议使用不同文案；“暂停/结束”不得写成失败。
- 相关作品失效时保留关系说明并显示不可用，不删除关系。
- 时间线按 `happenedAt DESC, eventId ASC`。

### P09 作品比较

**功能**

- 顶部显示会话归属、保存状态和 2—5 个作品管理入口。
- 支持上移、下移、替换、移除、清空；已选作品不可再次加入。
- 默认“仅看差异”，可切换“查看全部”；相同字段折叠。
- 比较维度至少包含：用户与定位、输入输出、核心流程、练习反馈、开发方式、访问状态和复用资产。
- 每个单元格显示值/未知原因、时效和来源；异常/结束作品保留历史事实。
- 资产区集中展示所选作品公开资产；行动区保存继续、调整、复用或暂停。

**行动字段校验**

- 行动单选必填：继续、调整、复用、暂停。
- 受影响字段至少 1 项：目标用户、定位、功能、核心流程、技术路径、资产。
- 理由 `trim` 后 10—1000 字符。
- 关联资产可选，但必须属于当前比较作品且当前用户可访问。
- 保存行动时同时保存比较；同一会话同一用户首期只保留一条当前决策，修改时生成版本而非覆盖审计历史。

**异常**

- 0 个作品：引导返回选择；1 个作品：明确还需 1 个；2—5 个：进入比较。
- 会话不存在或无权访问时返回可操作错误页，不泄露会话内容。
- 写入冲突返回 409，保留本地行动草稿并允许基于最新会话重试。

### P10 发布入口

**功能**

- 登录后输入作品公开 URL，依次检查格式、安全、访问、重复和品类。
- URL 可省略协议，系统仅允许补全为 `https://`；规范化后回显并保存。
- 检查全部通过后才可创建新作品发布草稿。
- 访问检查超时允许保存地址草稿，但禁止继续发布，重试通过后恢复。
- 发现重复档案时禁止新建，优先查看已有详情；用户明确是作者且需要管理时进入认领；不是同一作品时进入纠错流程。

**URL 校验**

- 必填，`trim` 后 1—2048 字符。
- 仅 `http/https`，必须有有效域名；去除 URL fragment，主机名小写，默认端口移除。
- 安全失败、重复命中或不在首期收录范围时 `canCreateDraft=false`。
- 访问探测最多跟随 3 次重定向，单次任务超时 10 秒；重定向每一步重新执行 SSRF 校验。
- 查重至少比较规范化 URL、最终重定向 URL、历史 URL 和已建立别名；域名相同但路径不同只能作为候选，不自动判重。

**幂等与恢复**

- 同一用户和规范化 URL 只创建一个未完成草稿；重复点击返回已有草稿。
- 取消检查不得创建审核单或重复检查结果。
- 登录前输入通过会话草稿保留，登录后回到原页面自动回填，但不自动提交检查。

### P11 发布编辑与审核状态

**编辑流程**

1. 自动预填：名称、定义、截图、仓库、访问状态；
2. 产品定义：目标用户、核心问题、使用场景；
3. 方案与功能：输入、输出、核心流程、练习形式、反馈方式、差异化；
4. 开发与资产：Vibe Coding 工具、关联公开资产；
5. 预览并提交审核。

- 自动提取内容必须标明来源并允许修改；失败字段可手填，非必填字段可跳过。
- 每次字段失焦或 2 秒无输入后自动保存；页面离开前若仍有未保存内容，先执行一次保存。
- 用户只能打开自己的草稿；草稿不存在、属于其他用户或已删除时返回不可访问提示。
- 提交前展示社区卡片和详情摘要；提交后冻结 `submittedFields` 和 `submittedAssetIds`。

**审核状态**

```text
draft → pending_review
pending_review → approved | changes_requested | rejected | restricted | withdrawn
changes_requested → pending_review | withdrawn
withdrawn → draft
approved/rejected/restricted 为本次审核终态，重新发布必须创建新的审核版本
```

- 待审核不展示无依据的倒计时。
- 需修改必须按字段给出意见，并可直接定位对应步骤。
- 补充材料仅供审核，不改写冻结提交版本。
- 撤回停止当前审核，但保留提交快照和审核历史。
- 通过后原子生成公开作品、首次发布事件和提交者通知；任何一步失败都不得出现半发布状态。

### P12 作者身份验证

**功能**

- 证明方式：域名控制、代码仓库、原发布账号、公开主页、其他材料。
- 必填材料摘要和私有材料引用，材料只在有权限的审核后台显示。
- 申请人可查看状态历史，需补充或失败时可更新材料重新提交。
- 验证成功后开放该作品的作者管理权限；争议时冻结高风险编辑。

**状态**

```text
draft → pending
pending → changes_requested | verified | failed | disputed | withdrawn
changes_requested/failed → pending
disputed → pending | verified | failed（仅管理员处理）
```

**字段校验与隐私**

- 证明方式必选。
- 材料摘要 `trim` 后 10—500 字符，不得包含密码或访问令牌。
- 私有材料引用 1—2000 字符；支持 HTTPS 链接或平台上传文件 ID，不在前台、公开 API、埋点和普通审计日志中出现。
- 上传文件类型限 PDF/JPG/PNG，单文件不超过 10 MB，最多 5 个；执行恶意文件扫描。
- 验证材料的保存期限和删除策略须在上线前完成隐私评审；产品默认在审核终态后按政策最短化保留。

### P13 作品更新

**权限**

- 仅作品已关联作者或验证请求状态为 `verified` 的当前用户可提交。
- 权限过期返回 403，保留草稿并引导重新验证；争议返回冻结状态。

**更新类型**

- 版本：新版本名称/编号。
- 地址：新公开地址，旧地址写入历史。
- 状态：仅正常、已恢复、暂停、结束；暂停/结束必须勾选作者明确声明。
- 说明：新的一句话介绍。
- 资产：名称、类型、公开地址、可选许可证。

**通用校验**

- 更新值、来源说明和影响范围必填；来源说明和影响范围分别为 10—500 字符。
- 来源类型必选：作者声明、公开页面、代码仓库、发布说明。
- 版本名称 1—80 字符；说明 1—180 字符。
- 地址和资产地址仅允许安全的完整 HTTP/HTTPS URL。
- 资产名称 1—80 字符，许可证 0—100 字符；资产类型使用固定枚举。
- 提交前显示前后值并二次确认；成功后原子更新当前事实、追加事件、保存更新记录并生成关注者通知。
- 使用幂等键防止重复事件和重复通知。

### P14 作者主页

**功能**

- 展示作者名称、简介、验证状态、公开联系方式和分享入口。
- 只把 `authorLinkStatus=linked` 的作品计入作者作品；待确认作品单独提示，不计入公开作品数。
- 展示已确认作品的最近 6 条事件、未移除公开资产和被复用关系。
- 作者身份争议时继续显示已确认公开事实，但不扩展新归属关系。

**排序**

- 作者作品：最近公开事件时间倒序，无事件按首次发布时间倒序。
- 最近更新：`happenedAt DESC, eventId ASC`，最多 6 条。
- 资产：可用优先、最近核验时间倒序、资产 ID。

### P15 个人中心

**模块**

- 收藏：直接返回作品，并在此切换关注更新。
- 比较记录：按 `updatedAt DESC`。
- 最近浏览：最近访问优先，去重后最多 20 个。
- 发布草稿：仅 `draft`，按 `updatedAt DESC`。
- 审核记录：非草稿提交，按 `updatedAt DESC`。
- 比较决策：仅本人，按 `createdAt DESC`。
- 作者身份验证：仅本人，按 `updatedAt DESC`。
- 我的作品与更新草稿：仅有作者身份时展示。
- 平台管理入口：仅编辑和管理员展示。

**规则**

- 关注按钮只出现在收藏列表；取消收藏后该作品从列表移除且同步取消关注。
- 数据按当前用户服务端查询，切换账号不得短暂显示上一个账号的数据。
- 列表引用已合并作品时自动指向主档；引用已限制/删除作品时保留记录并解释不可访问原因。

### P16 通知中心

**通知类型**

- 作品更新、评论回复、发布审核、身份审核、状态异常。

**功能与排序**

- 默认按 `createdAt DESC, notificationId ASC`，支持类型筛选和只看未读。
- 支持单条标已读、打开并定位、全部标已读。
- 打开通知先标已读，再校验目标路径和权限；目标不可访问时保留通知并解释原因。
- 未读数使用服务端计数或增量推送，不通过前端全量列表推断。

**去重**

- 作品更新通知唯一键：`eventId + recipientUserId`。
- 审核通知唯一键：`reviewVersionId + decision + recipientUserId`。
- 评论回复唯一键：`commentId + recipientUserId`。

### P17 登录/注册

**功能**

- 支持正式账户登录/注册；原型中的固定身份选择器不得进入生产环境。
- 登录后安全返回原页面并回放一次待完成操作。
- 若存在游客比较，登录前明确提示“登录后将保存当前 N 个作品，不会自动合并历史比较”。
- 登录失败保留 `from`、临时比较和未提交输入；退出后清除当前设备上的账户私有缓存，但不删除服务端数据。

**安全**

- 会话使用安全、HttpOnly、Secure、SameSite Cookie；敏感写操作使用 CSRF 防护。
- 连续失败触发速率限制和通用错误文案，不泄露账户是否存在。
- `from` 只允许站内绝对路径。

### P18 关于与收录规则

- 面向用户说明产品定位、收录/不收录范围、状态含义、来源类型、作品进入社区的方式、认领和纠错。
- 文案不得出现任务编号、开发阶段、组件名、数据库规则或“首期结构设计”等内部说明。
- 规则更新必须有版本号和生效时间；重要范围变化需要在发布入口同步提示。

## 8. 后台页面与工作流

### A01 后台看板

- 展示作品总量、待审核、访问异常、资料待补全和作者关联待处理数量。
- 数量只表示工作队列，不输出业务增长或市场结论。
- 执行一致性检查：项目/事件/通知 ID 去重、别名目标存在、副档归档、发布同步、身份同步和状态同步。
- 一致性异常必须给出目标 ID 和处理入口；看板接口失败不影响进入具体队列。

### A02 作品队列

- 搜索名称、定义、`projectId` 和公开地址。
- 筛选品类、发布状态、访问状态、完整度、作者关联、只看待审核、只看异常；全部写入 URL。
- 默认排序：待审核优先、活动异常优先、最久未核验优先、`projectId ASC`。
- 表格展示作品、品类、发布状态、访问状态、完整度、作者关联、核验时间和编辑入口。
- 后台以桌面工作台为主，窄屏允许表格内部横向滚动，不允许页面整体溢出。

### A03 作品编辑与证据复核

**普通可编辑字段**

- 名称、定义、核心问题、目标用户、使用场景、输入、输出、练习形式、反馈方式、差异化、核心/次要功能、技术栈、模型、部署平台、开发周期。
- 名称 1—80 字符；一句话定义 1—180 字符；核心问题 1—500 字符。
- 目标用户、使用场景、输入和输出各至少 1 项。
- 多行功能/技术字段去空白、去重，每项最多 100 字符，单字段最多 30 项。
- 原始收录平台仅管理员可编辑。

**受保护字段**

- 当前公开地址、访问状态、发布状态、作者关联、完整度、核心历史、资产和关系不能通过普通保存修改；必须进入专用工作流。
- 每次保存必须填写 10—500 字符原因，并对每个变化字段追加前值、后值、操作者、时间和原因。
- 使用乐观锁版本号；发生 409 时展示打开时版本、后台最新版本和用户未保存版本，不得静默覆盖。

**证据复核**

- 可将证据标记为当前、过期、证据不足或争议；必须填写原因。
- 状态操作只更新复核标记和审计日志，不删除来源、稳定证据 ID 或历史引用。
- 来源不存在时显示空状态并引导补充，不得猜测。

### A04 重复与合并

- 候选组展示名称、地址、稳定 ID、版本、事件和资产数量，管理员选择主档。
- 合并前预览名称/地址历史、版本、事件、资产、关系、作者和互动数的处理结果。
- 执行时必须填写原因并二次确认；操作具备幂等性。
- 主档保留稳定 ID；副档标记归档，旧 ID 建永久映射；所有引用在同一事务或可补偿任务中迁移。
- 合并失败不得产生半迁移引用；重试使用同一幂等键。

### A05 发布审核

- 审核动作：通过、退回补充、拒绝、标记争议；全部必须填写原因并二次确认。
- 编辑可通过、退回、拒绝；只有管理员可标争议和限制已发布作品展示。
- 同一提交版本只允许一个有效审核决定；并发决定返回 409 并刷新最新审核单。
- 通过必须原子生成作品、首次事件、审核日志和通知。
- 限制展示不删除作品、来源、历史或作者材料。

### A06 作者身份审核

- 仅本页读取私有材料；公开页面、公开 API、公开证据和通用日志禁止包含材料原文或引用。
- 编辑可要求补充；只有管理员可通过、失败或标记争议。
- 所有操作必须填写原因并二次确认，同步更新申请状态、作品作者关联、申请人通知和不可删除日志。
- 审核日志只保存结果、原因和材料对象 ID，不保存私有材料内容。

### A08 证据管理

- 首期不建设独立的证据操作工作台；`/admin/evidence` 只作为路由说明或跳转到 A03 的证据复核模块。
- 所有证据查看、打开原始来源、标记过期/不足/争议和审计日志均在 A03 内完成，避免两套写入口产生状态冲突。
- 若保留 `/admin/evidence` 路由，必须返回明确说明和“进入作品队列”入口，不得出现无功能空白页。
- 后续独立建设时仍需复用同一 Evidence 实体、权限与审计接口，不能复制证据数据。

### A09 状态监测

- 技术异常首先进入待复查。首次人工记录无论选择何种拟定状态，都不得改写前台状态。
- 第二次及后续复核可由管理员确认公开状态并追加生命周期事件。
- 编辑可记录首次检查；最终状态确认仅管理员。
- 暂停或结束必须有作者明确声明或足够人工证据；单次 URL 异常不满足条件。
- 每次操作必须填写原因，显示技术信号、当前公开状态、复核次数和历史日志。

## 10. 枚举、排序与推荐规则

### 10.1 关键枚举

**访问状态**

| 值 | 用户文案 | 产生方式 |
| --- | --- | --- |
| `normal` | 正常访问 | 技术检查或人工核验 |
| `login_required` | 登录后访问 | 人工/作者确认 |
| `pending_recheck` | 等待复查 | 首次异常工作流 |
| `partial_abnormal` | 部分异常 | 多步骤人工确认 |
| `link_unavailable` | 链接不可用 | 重复检查后人工确认 |
| `suspected_migration` | 疑似迁移 | 旧/新地址待核对 |
| `paused` | 暂停维护 | 作者声明或管理员依据充分确认 |
| `ended` | 已结束 | 作者声明或管理员依据充分确认 |
| `recovered` | 已恢复 | 技术检查后人工确认或作者更新 |
| `unknown` | 未知 | 证据不足 |

**资产类型**：源代码、模板、组件、提示词、解析方案、开放 API、部署方案、其他。

**作者关联**：未关联、待审核、已关联、失败、争议。

**资料完整度**：完整、部分完整、资料有限、等待核验、争议。完整度由字段规则计算，不能人工作为营销标签随意设置。

### 10.2 搜索与想法匹配

- 普通搜索采用可解释的文本和结构化字段混合评分。建议权重：名称 5、核心问题 4、一句话定义 3、使用场景 3、输入 2、练习形式 2、作者/工具 1。
- 中文别名词典首期支持 PDF、口语、背词、听写、错题、模考、出题等，词典由运营配置并版本化。
- 精确想法匹配使用“每个非空意图维度均至少命中一项”的 AND 规则；维度内部使用 OR。
- 任何排序都必须有稳定兜底键 `projectId ASC`，防止翻页重复或跳项。
- 结果中必须返回 `matchedFields` 或匹配解释，禁止只返回不可解释分数。

### 10.3 代表作品

在符合页面条件的候选中计算：

```text
representative_score =
  资料完整 +4
  至少一项公开可复用资产 +2
  信息仍在有效期 +1
```

按 `representative_score DESC, lastVerifiedAt DESC, projectId ASC` 取第一项。运营可通过显式 `editorial_rank` 覆盖首页编辑精选，但不能覆盖状态、权限和公开性过滤。

### 10.4 通用分页

- 作品、事件、通知和后台队列使用游标分页，不使用可能跳项的深度 offset。
- 前台每页默认 20，最大 50；后台默认 50，最大 100。
- 游标包含主排序值和稳定 ID；筛选变化后游标失效并从第一页开始。

## 11. 异常处理与恢复

### 11.1 标准错误模型

```json
{
  "code": "VC_STABLE_ERROR_CODE",
  "message": "面向用户的可行动说明",
  "kind": "validation|unauthorized|forbidden|not_found|conflict|rate_limit|network|timeout|server",
  "retryable": true,
  "fieldErrors": { "fieldKey": "字段错误" },
  "requestId": "服务端请求 ID"
}
```

- 用户界面显示可执行下一步，不直接展示堆栈、SQL、供应商错误或敏感信息。
- 日志使用 `requestId` 关联，稳定 `code` 用于监控和自动化测试。
- 可重试写操作必须携带幂等键；客户端超时后先查询写入结果，再决定重试。

### 11.2 场景处理矩阵

| 场景 | 页面行为 | 数据行为 |
| --- | --- | --- |
| 网络断开/超时 | 保留输入、筛选和滚动；显示重试 | 不清空草稿，不重复写入 |
| 服务 5xx | 局部错误优先；提供重试与返回 | 事务回滚，记录 requestId |
| 401 未登录 | 跳登录并保留安全回跳 | 待办动作只回放一次 |
| 403 无权限 | 说明当前身份与可用出口 | 不泄露私有对象内容 |
| 404 不存在 | 展示资源不存在和返回入口 | 已合并 ID 先解析别名 |
| 409 并发冲突 | 展示最新版本与本地输入 | 不静默覆盖，允许合并/刷新 |
| 422 字段错误 | 字段旁提示并聚焦首错 | 返回稳定字段键 |
| 429 频率限制 | 显示稍后重试时间 | 保留输入，不自动循环请求 |
| 空结果 | 解释当前条件并提供清除/修改 | 与服务错误区分 |
| 外链风险 | 阻止跳转，允许取消/报告 | 记录风险结果，不请求危险目标 |
| 目标通知失效 | 保留通知并解释无法打开 | 已读状态可保留，目标不泄露 |
| 提交/更新权限过期 | 保留服务端草稿并引导重新验证 | 不创建半成品事件或通知 |
| 重复审核请求 | 刷新现有审核单 | 唯一约束阻止重复决定 |

### 11.3 降级规则

- AI 想法解析失败：降级为手动标签编辑和关键词搜索。
- 页面自动提取失败：保留 URL，允许填写必填字段；提取失败不等于 URL 检查失败。
- 搜索索引暂不可用：允许回退到名称/定义基础搜索，并明确“结果可能不完整”。
- 通知推送失败：写入站内通知后重试推送，不回滚已成功的作品更新。
- 状态探测失败：只记录技术检查失败，保持当前公开状态。

### 12.3 写操作一致性

- 收藏、关注、已读状态使用“设置为 true/false”的 PUT/DELETE 语义，不用无法确定最终状态的纯 toggle API。
- 发布通过、身份审核、作品更新、重复合并和状态确认使用数据库事务或具备可补偿的工作流。
- 所有关键写操作接收 `Idempotency-Key`，服务端至少保留 24 小时去重记录。
- 数据修改使用 `version` 或 `updatedAt` 乐观锁；冲突返回最新对象摘要。
- 审计日志和生命周期事件不可由普通业务 API 删除或原地改写。

## 13. 埋点方案

### 13.1 公共字段

所有事件包含：

```text

session_id, user_role, page_id, route, referrer_page_id,
```

### 13.3 核心漏斗

1. **发现漏斗**：搜索提交 → 结果展示 → 作品详情 → 加入比较 → 开始比较 → 保存行动。
2. **想法漏斗**：自动进入想法分析 → 解析完成 → 标签确认 → 精确结果 → 开始比较 → 保存行动。
3. **新作品发布漏斗**：URL 检查 → 无重复 → 完成四步 → 提交审核 → 通过 → 进入详情。
4. **已有作品认领漏斗**：URL 检查 → 重复命中 → 查看已有档案 → 提交身份材料 → 验证通过 → 首次更新。
5. **更新回访漏斗**：个人中心 → 作品更新 → 事件发布 → 关注者收到通知 → 打开并定位。

- 核心任务满足 WCAG 2.2 AA 基线。
- 键盘和读屏可完成搜索、筛选、比较、登录、发布、身份验证、作品更新、弹层关闭和后台确认。
- 焦点清晰且可恢复；表单错误与字段通过 `aria-describedby` 关联；动态状态使用合适的 live region。
- 信息不只依赖颜色；支持 `prefers-reduced-motion`。
- 360、390、768 和桌面视口无页面级横向滚动，不通过缩小正文或删除关键信息适配。
- 后台表格可在自身容器内滚动，但操作按钮和表头仍可访问。

### 14.2 性能

- 公开核心页移动网络 p75：LCP ≤2.5 秒、INP ≤200 ms、CLS ≤0.1。
- 搜索与列表 API p95 ≤1 秒；详情 p95 ≤800 ms；普通写操作 p95 ≤1.5 秒，不含异步抓取/审核任务。
- 首屏只加载当前页面必要数据；媒体懒加载，路由级代码拆分。
- 搜索、详情和公开作者页支持 CDN/服务端缓存；用户私有页和后台禁止公共缓存。

### 14.3 安全与隐私

- 服务端 RBAC、对象所有权校验、CSRF/XSS/SSRF 防护、上传扫描和速率限制为上线门槛。
- 私有身份材料独立存储、加密传输与静态加密，仅授权审核人员短期访问。
- 日志、埋点和错误追踪不得包含私有材料、完整长文本、密码、Token 或 Cookie。
- 用户生成内容做输出编码；评论、作品文本和审核原因不允许直接渲染 HTML。
- 公开页面生成规范链接；个人中心、通知、提交、身份和后台页面设置 `noindex`。

### 14.4 可观测性

- 监控接口错误率、p95 延迟、搜索零结果率、解析失败率、发布事务失败、重复审核、通知去重失败和一致性检查异常。
- 发布、合并、身份审核、状态确认和作品更新必须有业务审计指标与告警。
- 告警必须带 `requestId`、对象 ID、动作和环境，不能包含隐私正文。

## 15. 验收标准

### 15.1 四条核心流程

**AC-F01 广场到比较行动**

- Given 游客从广场、分类或搜索选择作品，When 加入 2—5 个作品，Then 比较栏数量、比较页顺序和返回上下文一致。
- Given 游客已选 2 个作品，When 登录保存，Then 当前 2 个作品归属登录账户，且不混入账户历史作品。
- Given 用户保存行动，When 刷新或从个人中心返回，Then 比较、行动和关联资产可恢复且仅本人可见。

**AC-F02 统一搜索到同类分析**

- Given 短关键词，When 提交统一搜索，Then 进入 `/search` 并展示匹配原因。
- Given 满足完整想法规则的长文本，When 提交，Then 进入 `/discover`，原文完整保留且标签可编辑。
- Given 精确结果少于 3 个，Then 显示相近作品；Given 为 0，Then 显示相关专题和修改条件，不显示市场结论。

**AC-F03 发布与查重分流**

- Given URL 格式、安全、访问、查重和品类全部通过，When 用户完成必填步骤并确认，Then 创建一份冻结提交版本并进入待审核。
- Given 查重命中，Then 不提供新建按钮；用户可查看已有档案、认领或纠错。
- Given 审核通过，Then 作品、首次事件、审核日志和通知要么全部成功，要么全部失败，不出现半发布。

**AC-F04 认领、更新与回访**

- Given 未验证用户提交私有材料，Then 前台、公开 API、埋点和普通日志均无法读取材料。
- Given 管理员验证通过，Then 同步开放管理权限、更新作者关联并通知申请人，但不新建作品。
- Given 已验证作者更新作品，Then 当前字段、时间线、动态、更新记录和关注者通知保持一致；旧值仍可追溯。

### 15.3 发布门槛

- P01—P18、A01—A06/A08/A09 和 AC-F01—F04 均有对应接口契约、研发任务与自动化测试映射。

- 权限测试证明横向越权、对象猜测和仅靠前端限制均不可成功。
- 发布事务、身份审核、重复合并、状态确认的一致性检查全部通过。

- 性能、安全、备份恢复和隐私评审通过；不存在 P0/P1 未关闭缺陷。

## 16. 上线前待确认项

以下项目不改变页面主流程，但必须在开发排期前由负责人确认：

1. 正式登录方式（邮箱验证码、第三方账号或两者并存）及账户合并规则；
2. AI 想法解析与页面提取的具体服务、成本上限和失败降级 SLA；
3. 首期分类目录、同义词词典和编辑精选的运营负责人；
4. 身份材料的正式保存期限、删除机制和审核人员范围；
5. 评论审核策略、举报阈值和申诉入口；
6. 站内通知之外是否接入邮件，以及用户退订规则；
7. 公开作品截图采用用户上传还是受控抓取；
8. 首批真实作品导入、证据核验和作者联系计划。

以上待确认项必须形成决策记录。未确认时允许开发使用可替换接口，但不得把原型固定值写入生产业务逻辑。
